# Awesome RAG [![Awesome](https://awesome.re/badge.svg)](https://awesome.re)

RAG grounds language models in external knowledge: retrieve the right passages, then generate answers from them. This list covers the full stack — from document parsing and chunking, through embeddings and vector search, to reranking, evaluation, and the research frontier.

## Frameworks & libraries

*End-to-end RAG frameworks and orchestration libraries.*

- [LlamaIndex](https://github.com/run-llama/llama_index) — Open-source Python data framework for building LLM applications over private data: data connectors, indexing/structuring tools, and advanced retrieval/query interfaces for RAG and agentic apps. Data connectors for APIs, PDFs, docs, SQL and more; 300+ integration packages for LLM, embedding, and vector-store providers; Document parsing/extraction via LlamaParse; Workflows and document agents. ✅ verified 2026-09-30 *(Company focus has shifted toward LlamaParse; the OSS framework remains available (MIT) per its README.)*
- [LangChain](https://github.com/langchain-ai/langchain) — Open-source framework for building agents and LLM-powered applications, with a standard interface for models, embeddings, vector stores, retrievers, and composable chains. Standard interfaces for models, embeddings, vector stores, and retrievers; Large integration library for real-time data augmentation; LangGraph for controllable agent orchestration; LangSmith for evals, observability, and debugging. ✅ verified 2026-09-30
- [Haystack](https://github.com/deepset-ai/haystack) — Open-source AI orchestration framework for building production-ready LLM applications in Python, with modular pipelines and agent workflows with explicit control over retrieval, routing, memory, and generation. Modular pipelines with retrieval, ranking, filtering, and routing components; Agent lifecycle hooks and built-in tracking of steps, token usage, and tool calls; Native async support and token-by-token streaming; Model- and vendor-agnostic integrations. ✅ verified 2026-09-30
- [RAGFlow](https://github.com/infiniflow/ragflow) — Open-source RAG engine (Apache 2.0) that fuses RAG with agent capabilities as a context layer for LLMs, with a web UI and APIs for document ingestion, chunking visualization, and agentic retrieval. Agentic retrieval with Low/Medium/High/Ultra thinking modes; Template-based chunking with visualization and human intervention; Knowledge compilation into Wikis, Graphs, Trees, Mind Maps, and Timelines; Multiple recall paired with fused re-ranking. ✅ verified 2026-09-30
- [Verba](https://github.com/weaviate/Verba) — Community-driven open-source RAG chatbot application (BSD-3-Clause) powered by Weaviate, offering an end-to-end interface for retrieval-augmented generation with local or cloud LLM providers. Hybrid search combining semantic and keyword search; Support for Ollama, OpenAI, Anthropic, Cohere, HuggingFace, Groq, and more; Multiple chunking techniques (token, sentence, semantic, recursive, code, JSON); Docker deployment and 3D vector viewer. ✅ verified 2026-09-30 *(Discontinued by Weaviate; repository archived and read-only, no further updates.)*
- [txtai](https://github.com/neuml/txtai) — All-in-one AI framework (Apache 2.0) for semantic search, LLM orchestration, and language model workflows, centered on an embeddings database combining vector indexes, graph networks, and relational storage. Embeddings database unifying sparse/dense vector indexes with graph and SQL querying; RAG pipelines with citations, plus GraphRAG and speech-to-speech RAG examples; Agents built on smolagents connecting embeddings, pipelines, and workflows; Web and MCP APIs with JavaScript, Java, Rust, and Go bindings. ✅ verified 2026-09-30
- [R2R](https://github.com/SciPhi-AI/R2R) — Advanced AI retrieval system (MIT) for agentic RAG with a RESTful API and Python/JS SDKs, including a Deep Research API for multi-step reasoning over a knowledge base and the internet. Hybrid search (semantic + keyword) with reciprocal rank fusion; Multimodal ingestion of txt, pdf, json, png, mp3, and more; Knowledge graphs with automatic entity and relationship extraction; User and access management with authentication and collections. ✅ verified 2026-09-30
- [RAGatouille](https://github.com/AnswerDotAI/RAGatouille) — Library (Apache 2.0) for easily using and training state-of-the-art late-interaction retrieval models (ColBERT) in any RAG pipeline, covering training, indexing, and document retrieval with strong defaults. Train and fine-tune ColBERT models with built-in training-data processing; Create compressed, on-disk ColBERT indexes from documents; Search indexes with ranked results including content, scores, and metadata; Integrations with Haystack, LlamaIndex, LangChain, and Vespa. ✅ verified 2026-09-30 *(Repository renamed/moved from bclavie/RAGatouille to AnswerDotAI/RAGatouille; canonical URL used here.)*
- [LangChain4j](https://github.com/langchain4j/langchain4j) — Idiomatic open-source Java library for building LLM-powered applications on the JVM, with a unified API over LLM providers and embedding stores and easy agents and RAG pipelines in Java. Unified API over 20+ LLM providers and 30+ embedding (vector) stores; Toolbox spanning prompt templating, chat memory, function calling, agents, and RAG; Dedicated easy-rag module for RAG pipelines; Integrations with Quarkus, Spring Boot, Helidon, and Micronaut. ✅ verified 2026-09-30
- [fastRAG](https://github.com/IntelLabs/fastRAG) — Research framework (Apache 2.0) for efficient retrieval-augmented generative pipelines, providing optimized embedders, rankers, and ColBERT/PLAID components compatible with Haystack. Optimized int8 bi-encoders and sparse cross-encoder rankers; ColBERT token-based late interaction with PLAID indexing; Fusion-in-Decoder and REPLUG generative multi-document components; Haystack-compatible components. ✅ verified 2026-09-30 *(Archived by Intel Labs; no maintenance, bug fixes, or new releases. Included as a historically notable RAG research framework.)*

## Vector databases & retrieval infrastructure

*Vector databases, search engines with vector support, and ANN libraries.*

- [Pinecone](https://www.pinecone.io/) — Fully managed proprietary vector database built for AI, with instant-write indexing and fast vector queries at scale, managed through a console or terminal. Fully managed vector database with no infrastructure to operate; Automatic indexing with no tuning required; Enterprise governance, compliance, and reliability controls. ✅ verified 2026-09-30
- [Weaviate](https://github.com/weaviate/weaviate) — Open-source, cloud-native vector database written in Go that stores objects and vectors together, combining vector similarity search with keyword filtering, generative (RAG) search, and reranking in a single query interface. Advanced hybrid search combining semantic and keyword (BM25) search; Built-in generative search (RAG) and reranking capabilities; Automatic vectorization at import via integrated embedding models; Horizontal scaling, multi-tenancy, replication, and RBAC. ✅ verified 2026-09-30
- [Qdrant](https://github.com/qdrant/qdrant) — Vector similarity search engine and database (Apache 2.0) written in Rust, providing a production-ready service to store, search, and manage points (vectors with JSON payload). Dense, sparse, and multi-vector search including ColBERT-style late interaction; Rich payload filtering combined with hybrid search fusion (RRF, DBSF); Built-in vector quantization with tunable speed/precision trade-offs; REST and gRPC APIs, distributed deployment with sharding and replication. ✅ verified 2026-09-30
- [Milvus](https://github.com/milvus-io/milvus) — High-performance, cloud-native vector database (Apache 2.0) built for scalable ANN search, organizing and searching vast amounts of unstructured data with a distributed, Kubernetes-native architecture. All major vector index types (HNSW, IVF, FLAT, DiskANN) with GPU indexing support; Hybrid search combining dense vectors with native full-text/BM25 and sparse embeddings; Real-time streaming updates with horizontal scaling and high availability; Multi-tenancy, RBAC, TLS, and hot/cold storage tiers. ✅ verified 2026-09-30
- [Chroma](https://github.com/chroma-core/chroma) — Open-source data infrastructure for AI (Apache 2.0) centered on embeddings search, with a minimal 4-function Python/JS API that runs in-memory, persisted locally, or as a client-server deployment. Core API of four functions: create_collection, add, query, get; Automatic tokenization, embedding, and indexing with optional custom embeddings; Metadata filtering and persistence from in-memory prototyping to server mode; Managed Chroma Cloud service alongside the open-source engine. ✅ verified 2026-09-30
- [pgvector](https://github.com/pgvector/pgvector) — Open-source vector similarity search extension for Postgres, storing vectors alongside the rest of relational data with exact and approximate nearest neighbor search under Postgres ACID semantics. HNSW and IVFFlat approximate nearest neighbor indexes; Single-precision, half-precision, binary, and sparse vector types; L2, inner product, cosine, L1, Hamming, and Jaccard distance operators; ACID compliance, point-in-time recovery, and JOINs with relational data. ✅ verified 2026-09-30
- [Elasticsearch](https://github.com/elastic/elasticsearch) — Distributed search and analytics engine that also serves as a vector database, supporting near-real-time search over massive datasets including vector search and RAG integrations. Vector search and hybrid retrieval for RAG use cases; Full-text search alongside vector search in one engine; Distributed RESTful architecture with language clients; Kibana integration and managed deployments on Elastic Cloud. ✅ verified 2026-09-30 *(Elastic's server-side source code is under Elastic License/SSPL terms, not an OSI open-source license.)*
- [OpenSearch](https://github.com/opensearch-project/OpenSearch) — Open-source, Apache 2.0 distributed search and observability suite; a community-driven fork of Elasticsearch used for search over unstructured data at scale. Open-source distributed and RESTful search engine; Enterprise-grade search and observability suite; Apache 2.0 license with Linux Foundation governance. ✅ verified 2026-09-30
- [Vespa](https://github.com/vespa-engine/vespa) — AI search platform (Apache 2.0) for search, inference, and organizing vectors, tensors, text, and structured data at serving time and any scale, used by large internet services serving high query volumes. Unified search, ranking, and ML inference over vectors, tensors, and text at serving time; Designed for sub-100ms query latency over continuously changing corpora; Free trial cloud deployments plus self-hosted operation. ✅ verified 2026-09-30
- [Typesense](https://github.com/typesense/typesense) — Fast, typo-tolerant search engine (GPL-3.0) positioned as an open-source alternative to Algolia, Pinecone, and Elasticsearch, supporting vector search, semantic/hybrid search, and built-in conversational RAG. Vector search on embeddings with nearest-neighbor retrieval; Semantic/hybrid search with built-in embedding models or external providers; Conversational search (built-in RAG) generating answers over indexed data; Single-binary deployment with Raft-based clustering. ✅ verified 2026-09-30 *(GPL-3.0 licensed; check license implications for commercial use.)*
- [LanceDB](https://github.com/lancedb/lancedb) — Developer-friendly open-source embedded retrieval library (Apache 2.0) for multimodal AI built on the Lance columnar format, running locally or in the cloud for vector, full-text, and SQL search. Vector similarity, full-text, and SQL search over multimodal data; Built on the Lance columnar format for storage and analytics; Automatic versioning and zero-copy data management; Python, Node.js, Rust, and REST SDKs with LangChain/LlamaIndex integrations. ✅ verified 2026-09-30
- [FAISS](https://github.com/facebookresearch/faiss) — Library (MIT) for efficient similarity search and clustering of dense vectors, developed at Meta's Fundamental AI Research group, with indexes scaling from in-memory to datasets that do not fit in RAM. L2, dot product, and cosine similarity search with exact and approximate indexes; GPU-accelerated indexes as drop-in replacements for CPU indexes; Compact quantization codes scaling to billions of vectors on a single server; C++ core with complete Python/numpy wrappers. ✅ verified 2026-09-30

## Hybrid search, reranking & retrieval models

*Sparse/dense retrieval models, rerankers, and hybrid ranking methods.*

- [SPLADE](https://github.com/naver/splade) — Learned sparse retrieval method that uses a BERT MLM head for query/document expansion, enabling explicit lexical matching over an inverted index; ships training, indexing, and retrieval code with pretrained weights and BEIR/PISA evaluation. sparse retrieval; query/document expansion; inverted-index retrieval; pretrained weights. ✅ verified 2026-09-30 *(GitHub reports its license as NOASSERTION.)*
- [ColBERT](https://github.com/stanford-futuredata/ColBERT) — Late-interaction retrieval model that encodes queries and documents into token-level embeddings scored with MaxSim contextual late interaction; includes indexing, search, training, ColBERTv2 plus PLAID, and a lightweight search server. late interaction; token-level embeddings; indexing and search; search server. ✅ verified 2026-09-30
- [ColPali](https://github.com/illuin-tech/colpali) — Visual document retrievers that embed document page images directly using vision-language models with multi-vector embeddings and ColBERT-style late interaction, capturing text, layout, charts, and other visual content. visual document retrieval; multi-vector embeddings; late interaction; MIT license. ✅ verified 2026-09-30 *(Repository moved from vidore/colpali to illuin-tech/colpali; the ColPali Engine package is deprecated while the repository and model family remain active with migration guidance.)*
- [ReinPool: Reinforcement Learning Pooling Multi-Vector Embeddings for Retrieval System](https://arxiv.org/abs/2601.07125) — Reinforcement-learning framework that selects and pools token-level multi-vector embeddings into compact, retrieval-optimized representations without manual importance labels. Inverse-retrieval objective with NDCG-based rewards; evaluated on ViDoRe V2 with three vision-language embedding models; single-vector compression of multi-vector representations. ✅ verified 2026-10-03
- [FlashRank](https://github.com/PrithivirajDamodaran/FlashRank) — Ultra-lightweight Python reranking library supporting pairwise and pointwise cross-encoder rerankers as well as listwise LLM rerankers. Apache-2.0. cross-encoder rerankers; LLM listwise rerankers; Apache-2.0. ✅ verified 2026-09-30 *(Verified canonical path is PrithivirajDamodaran/FlashRank.)*
- [Cohere Rerank](https://docs.cohere.com/reference/rerank) — Commercial Rerank API (v2) that takes a query and a list of documents and returns them ordered by relevance score, commonly used as a second-stage ranker in RAG pipelines; supports top_n, max_tokens_per_doc, and document metadata. relevance scoring; top_n filtering; commercial API. ✅ verified 2026-09-30
- [Voyage Rerank](https://docs.voyageai.com/reference/reranker-api) — Commercial rerank API (rerank-2.5 family) that scores a query against a list of documents and returns reranking results with relevance scores; supports up to 1,000 documents per request, top_k, return_documents, and truncation options. relevance scoring; top_k filtering; commercial API. ✅ verified 2026-09-30
- [BGE Reranker](https://github.com/FlagOpen/FlagEmbedding) — Open cross-encoder reranker model family (including bge-reranker-v2-m3) maintained in the FlagEmbedding toolkit for second-stage re-ranking in search and RAG pipelines. cross-encoder reranking; open weights; MIT-licensed toolkit. ✅ verified 2026-09-30 *(The models are distributed via the FlagEmbedding toolkit repository rather than a standalone repository.)*
- [RankGPT](https://arxiv.org/abs/2304.09542) — Research paper investigating generative LLMs such as ChatGPT and GPT-4 as re-ranking agents for information retrieval, and distilling their ranking ability into small specialized models via a permutation distillation scheme. LLM-based reranking; permutation distillation; research paper. ✅ verified 2026-09-30 *(Full title: 'Is ChatGPT Good at Search? Investigating Large Language Models as Re-Ranking Agents'.)*
- [Reciprocal Rank Fusion (RRF)](https://doi.org/10.1145/1571941.1572114) — Paper defining Reciprocal Rank Fusion, a simple unsupervised method for combining document rankings from multiple IR systems that consistently beats any individual system and the standard Condorcet Fuse baseline. Presented at SIGIR 2009. rank fusion; hybrid search; unsupervised; research paper. ✅ verified 2026-09-30 *(No arXiv version exists; the DOI above is the official ACM record for the SIGIR 2009 paper.)*

## Advanced RAG patterns

*Agentic RAG, graph-based RAG, corrective and self-reflective retrieval, multi-hop patterns.*

- [Annotation-Free Reinforcement Learning Query Rewriting via Verifiable Search Reward](https://arxiv.org/abs/2507.23242) — RL-QR trains query rewriting without human-annotated rewrites, deriving verifiable search rewards from index-aligned synthetic queries across retrieval modalities. Annotation-free reinforcement learning; index-aligned synthetic queries; lexical, semantic, and visual-document retrieval evaluation. ✅ verified 2026-10-03
- [GraphRAG](https://github.com/microsoft/graphrag) — Microsoft Research graph-based RAG system that extracts structured data from unstructured text to answer complex questions over private data. Graph-based targeted context for QA; Structured data extraction from unstructured text; CLI quickstart; Prompt-tuning guide. ✅ verified 2026-09-30 *(Official README states the project is largely in maintenance mode (no new features or PRs, bug fixes and dependency updates only) and is a research demonstration, not an officially supported Microsoft offering.)*
- [LightRAG](https://github.com/HKUDS/LightRAG) — Lightweight graph-based RAG implementation designed to be simpler and faster to set up than full GraphRAG pipelines. MIT-licensed and actively maintained. Lightweight graph-based RAG; Selectable query modes and reranking; Multiple storage backends; WebUI and API. ✅ verified 2026-09-30
- [nano-graphrag](https://github.com/gusye1234/nano-graphrag) — Compact, minimal GraphRAG implementation intended as a small, hackable codebase for experimenting with graph-based retrieval. MIT-licensed. Compact GraphRAG implementation; Local, global, and naive query modes; Async APIs; Incremental insertion. ✅ verified 2026-09-30
- [HippoRAG](https://github.com/OSU-NLP-Group/HippoRAG) — Neurobiologically inspired long-term-memory framework for LLMs that builds knowledge graphs from documents to support multi-hop retrieval. MIT-licensed. Long-term-memory-inspired framework; Knowledge connections and multi-hop retrieval; OpenAI-compatible and local vLLM endpoints; Qdrant, ChromaDB, and Milvus vector stores. ✅ verified 2026-09-30
- [Self-RAG](https://arxiv.org/abs/2310.11511) — Adaptive retrieval framework that trains a single language model to retrieve on demand and critique its own retrieved passages and generations using reflection tokens. On-demand retrieval; Reflection tokens; Critiques retrieved passages and generated output. ✅ verified 2026-09-30
- [Corrective RAG (CRAG)](https://arxiv.org/abs/2401.15884) — Corrective Retrieval Augmented Generation: adds a lightweight retrieval evaluator that triggers corrective actions, such as web search or document filtering, when retrieval confidence is low. Lightweight retrieval evaluator; Confidence-triggered retrieval actions; Web-search extension; Decompose-then-recompose filtering. ✅ verified 2026-09-30
- [RAPTOR](https://arxiv.org/abs/2401.18059) — Tree-organized retrieval: recursively embeds, clusters, and summarizes text chunks into a tree so retrieval can happen at multiple abstraction levels. Recursive embedding, clustering, and summarization of chunks; Tree retrieval across abstraction levels. ✅ verified 2026-09-30
- [HyDE](https://arxiv.org/abs/2212.10496) — Zero-shot dense retrieval method: an LLM generates a hypothetical document answering the query, which is embedded and used to retrieve real documents from the corpus. Generates hypothetical document; Embeds it as the query vector; Retrieves real documents from corpus embedding space. ✅ verified 2026-09-30
- [FLARE](https://arxiv.org/abs/2305.06983) — Active retrieval augmented generation: the model decides when and what to retrieve during generation, predicting the upcoming sentence and regenerating when confidence is low. Decides when and what to retrieve during generation; Predicts upcoming sentence; Regenerates on low-confidence tokens. ✅ verified 2026-09-30

## Papers & guides

*Foundational papers, surveys, and field guides.*

- [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401) — Foundational 2020 paper introducing RAG: parametric seq2seq memory combined with non-parametric dense retrieval over Wikipedia, fine-tuned end-to-end with retrieved documents as a latent variable. Set state of the art on three open-domain QA tasks. RAG-Sequence and RAG-Token formulations; Dense Passage Retriever over Wikipedia index; End-to-end fine-tuning with latent-variable marginalization; State-of-the-art on three open-domain QA tasks. ✅ verified 2026-09-30
- [Retrieval-Augmented Generation for Large Language Models: A Survey](https://arxiv.org/abs/2312.10997) — Comprehensive survey organizing RAG into Naive, Advanced, and Modular paradigms, covering indexing, retrieval, generation, augmentation techniques, and evaluation frameworks. Naive / Advanced / Modular RAG taxonomy; Tripartite foundation: retrieval, generation, augmentation; Evaluation frameworks and benchmarks; Open challenges and research directions. ✅ verified 2026-09-30
- [Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172) — Empirical study showing LLM performance on multi-document QA and key-value retrieval degrades when relevant information sits in the middle of long contexts; best at the beginning or end. Directly motivates reranking and context ordering in RAG. Multi-document QA and key-value retrieval analysis; Positional performance degradation finding; Evaluation protocols for long-context models. ✅ verified 2026-09-30
- [Ragas: Automated Evaluation of Retrieval Augmented Generation](https://arxiv.org/abs/2309.15217) — Introduces Ragas (Retrieval Augmented Generation Assessment): reference-free metrics for evaluating RAG pipelines across retrieval, faithfulness, and generation quality without human-annotated ground truth. Reference-free evaluation metrics; Separate retrieval, faithfulness, and generation dimensions; No ground-truth annotations required. ✅ verified 2026-09-30
- [Seven Failure Points When Engineering a Retrieval Augmented Generation System](https://arxiv.org/abs/2401.05856) — Experience report from three case studies (research, education, biomedical) cataloguing seven failure points in engineering RAG systems and arguing robustness emerges through operation rather than upfront design. Seven failure points: missing content, missed top-ranked docs, not in context, not extracted, wrong format, incorrect specificity, incomplete; Cross-domain case studies; Research directions for RAG robustness. ✅ verified 2026-09-30
- [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval) — Anthropic's official technique for improving RAG retrieval: prepending LLM-generated, chunk-specific context before embedding (Contextual Embeddings) and indexing (Contextual BM25). Reported to reduce top-20 retrieval failures by 49%, or 67% when combined with reranking. Contextual Embeddings; Contextual BM25; Reranking combination; Chunk-specific LLM-generated context. ✅ verified 2026-09-30
